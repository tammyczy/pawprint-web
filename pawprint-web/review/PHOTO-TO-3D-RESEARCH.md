# Pawprint 宠物 3D 建模研究与实验

2026 年 11 月 22 日。范围是 Studio 从宠物照片到带毛色、可转动和可预览行走的 GLB，以及网站上的蓝老样例。

## 技术路线

| 路线 | 对 Pawprint 的价值 | 本轮结论 |
| --- | --- | --- |
| Tripo H 系列单图或多图 | 同一条 API 能完成 PBR 网格、四足绑定和动作。原图贴图对齐可以保留输入色彩优先级。多图要求正面和至少一个额外角度，参考图应保持同一只宠物及相近光线。 | 继续使用 v3.1 几何作为默认。标准路线保留 50,000 面上限。新增高细节路线，独立请求细节几何、细节贴图和 80,000 面上限，纹理模型固定为 v3.5，保留照片原有光影。高细节作为显式选择，待真实宠物照片对照后再决定默认值。 [单图 API](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard) · [多图 API](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard) · [骨骼 API](https://developers.tripo3d.ai/en/docs/animations-rig) |
| 由单图补视角 | 有一张旧照也能继续。单张照片缺失的背面和侧面要由模型估计，左右花纹和尾巴仍要核对。 | Studio 展示原照和推测图。正面使用原照，补图逐张确认。侧背面都未通过时，用户可以直接用正面原照继续。确认后的路线读取本地保存的图像，减少依赖远端补图任务的保留期。 [补视角 API](https://developers.tripo3d.ai/en/docs/generation-image-to-multiview) · [Tripo 资产保留公告](https://developers.tripo3d.ai/en/blog/asset-retention-policy) |
| Tripo P2 或 Meshy | P2 提供较低面数和四边面选项，适合研究实时渲染。Meshy 的多图接口和四足绑定接口可以形成独立对照，绑定返回的走、跑动作可能缺一项。 | 保留为真实样本对照候选。先用同一套角度、动作和毛色评分衡量效果，再决定是否增加第二家服务或低面数路线。 [Tripo P 系列](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/p) · [Meshy 多图](https://docs.meshy.ai/en/api/multi-image-to-3d) · [Meshy 四足绑定](https://docs.meshy.ai/en/api/rigging#rig-a-four-legged-animal) |
| 自托管通用模型或猫狗专用模型 | TRELLIS.2 可生成带 PBR 材质的网格，官方实现需要 Linux 和至少 24 GB 的 NVIDIA 显存。3D-Fauna、SMAL-pets 和 AnimalLift 研究了从单图还原可动画动物，AnimalLift 还建模了毛发属性。Animal Avatars 利用视频共同估计运动与外观。 | 通用网格生成仍需四足绑定和浏览器交付。动物专用方法值得用来评估解剖、姿态和毛发，接入前要验证猫狗品种覆盖、GLB 输出、运行成本及模型授权。 [TRELLIS.2](https://github.com/microsoft/TRELLIS.2) · [3D-Fauna](https://openaccess.thecvf.com/content/CVPR2024/papers/Li_Learning_the_3D_Fauna_of_the_Web_CVPR_2024_paper.pdf) · [SMAL-pets](https://arxiv.org/abs/2603.17131) · [AnimalLift](https://arxiv.org/abs/2609.09513) · [Animal Avatars](https://remysabathier.github.io/animalavatar.github.io/) |

按 Tripo 当前价目，标准带贴图建模为 30 积分，高细节增加 30 积分。四足绑定和一个行走动作合计 35 积分，AI 补视角另计 10 积分。Studio 在提交前显示预计总价，每个阶段按服务商返回的实际积分核对。Tripo 自 2026 年 12 月 1 日起对标准 API 资产实行最长七天的保留期，具体企业协议以服务商约定为准。 [Tripo 价目](https://developers.tripo3d.ai/en/pricing) · [计费](https://developers.tripo3d.ai/en/docs/billing) · [保留公告](https://developers.tripo3d.ai/en/blog/asset-retention-policy)

## 实验一　照片与角度

选了两组本地猫狗参考图。以每组的正面为基准，比较原样复制、JPEG 重新编码、镜像、强模糊和大幅变暗，以及三张不同角度参考图。其中一组的侧背面来自已有的 AI 补图。

| 输入变化 | 旧上传流程 | 本轮对照结果 |
| --- | --- | --- |
| 完全重复 | 会提交到两个角度槽位 | 2/2 排除重复槽位，保留照片预览 |
| JPEG 重新编码或镜像 | 会直接提交 | 4/4 提示可能为同一角度，保留用户选择 |
| 强模糊或大幅变暗 | 会直接提交 | 4/4 出现对应提示 |
| 两组三个不同角度 | 会直接提交 | 6/6 保留，均未触发相似角度提示 |

最终以规范化 PNG 的字节指纹判断完全重复，并以缩小后的 RGB 差异判断普通和镜像近似。低分辨率、画面细节和亮度仅给出提示。固定背景、远处的小主体和对称毛色可能影响提示，真实角度、是否同一只宠物和可见的毛纹仍由用户核对。

## 实验二　骨骼与 GLB 验收

旧检查读取文件头、网格和动画名称。原始银渐层的静态模型可以通过这一检查。现在使用 Khronos Validator，并检查默认场景中的三角面、毛色来源和骨骼动画轨道。静态候选可以预览，行走候选需要骨骼绑定与有效时长的动作轨道。模拟任务验证了坏基础模型会在骨骼阶段前停止，失效的行走候选会保留彩色基础模型。 [Khronos glTF Validator](https://github.com/KhronosGroup/glTF-Validator)

另外追溯了蓝老的五个版本。未精修的基础模型为 0 项校验错误。肩髋重新分配权重后的精修源文件和旧网页包均报 10,165 项错误，涉及同一个关节在同一顶点被多次赋予权重，以及由此触发的权重检查。把 5,309 个重复影响合并到其原有骨骼以后，网页模型通过校验，错误降至 **0**。对照逐顶点验证了每根骨骼的总影响，并保留了已有的腿部精修和第二组权重。网页包维持约 6.7 MB，几何、UV、形变目标、骨骼层级和动画关键帧保留原数据。

## 实验三　网页模型体积

在四个仓库模型上比较原件、无损 WebP、近无损 WebP 和 Q92 WebP。百分比为完整 GLB 的字节节省量。RMSE 是替换的贴图中最大的每通道像素均方根误差，以 0–255 为单位。

| 样本 | 原件 | 无损节省 | 近无损节省 / RMSE | Q92 节省 / RMSE |
| --- | ---: | ---: | ---: | ---: |
| 蓝老基础 | 12.94 MB | 14.8% | 22.5% / 0.480 | 42.8% / 2.902 |
| 小Q | 4.21 MB | 12.5% | 12.9% / 0.087 | 48.8% / 1.206 |
| 银渐层原始动作 | 5.54 MB | 13.5% | 17.0% / 0.306 | 50.6% / 1.286 |
| 银渐层精修 | 8.98 MB | 31.1% | 33.7% / 0.453 | 65.4% / 1.286 |

无损路线在四个样本上保持贴图像素完全一致。新建任务采用它作为默认预览策略，节省达到 5% 时生成独立的预览文件。转换后再次验证 GLB，有需要时浏览器加载原件。原件始终是下载目标。压缩只替换图像缓冲区，网格、皮肤权重、形变和动作的数据保持逐字节一致。已发布的蓝老样例沿用它原有的贴图压缩参数。

```sh
node scripts/benchmark-modeling.mjs
node --test modeling.test.mjs server.test.js worker.test.js
```

## 付费试运营的验收设计

这次使用已归档的 3D 资产、可控的照片变化和模拟异步任务，验证了输入选择、模型技术质量与交付。高细节选项与原照加部分 AI 视角的相似度收益需要由真实生成评估。本轮未新增付费生成。

以 24 组获得授权的猫狗照片作为第一批对照，覆盖短毛、长毛、纯色和不对称花纹，并为每只宠物保留至少一张未输入的侧背面。对同一只宠物比较正面标准、真实多角度标准、正面加已选 AI 补图、真实多角度高细节。固定输入顺序、姿态、光线和渲染相机。记录模型版本、种子、每步积分和耗时，技术失败也保留在样本分母中。提供同一转台和行走视频，由主人和独立审阅者做盲配对。 [3D Arena 评估论文](https://arxiv.org/abs/2506.18787)

| 验收项 | 度量方式 |
| --- | --- |
| 毛色、花纹和体型 | 主人判断哪一版更像，同时与未输入的侧背面核对颜色、斑纹、口鼻、耳朵和尾巴。 |
| 四肢与行走 | 检查四肢数量和连接、网格塌缩、关节翻转、脚掌滑移及循环衔接。将技术通过、可展示与主人认可分别记录。 |
| 交付与单位成本 | 记录可用 GLB 比例、各设备首次出图时长、失败与重试成本、每个被接受模型的总积分。 |

用主人能明显辨认的改善和真实合格率决定高细节是否值得额外积分。通过技术检查的候选仍需核对相似度和动作表现，再作为用户的成品交付。
