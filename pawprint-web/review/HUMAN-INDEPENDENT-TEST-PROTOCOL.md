# Pawprint：真人独立动作测试准备方案

状态：方案草稿，尚未招募、收集数据或运行。它是团队建议，并非 WAICY 官方规定的样本数或取得某一分数的保证。

## 要验证的问题

人们用自己平常的话和数字宠物互动时，网站是否执行了他们想要的动作？是否发生未经请求的动作或遗漏明确的停止？分别检查离线规则、真实模型原始动作、服务器护栏及网页最终行为；不要把某一层的结果冒充完整网页表现。

## 人员及数据

1. 邀请未看过规则源码、既有案例及失败清单的自愿成年人独立写句子；用 A、B 等代号，不收真实姓名、联系方式、真实宠物故事或健康信息。给参与者说明目的、可跳过、可退出，以及保存/撤回边界。
2. 另请两位未参与调参的成年人独立标注用户希望的动作、是否需要停止当前动作，以及是否模糊；未达一致的条目保留双方判断和理由。不要为凑数强行确定答案。
3. 每条提供**开始状态**（例如静止、正在走、正在跑或未知）；明确没有背景时，不把「不开始某动作」一律等同「停止所有现有动作」。
4. 包含明确指令、否定、普通聊天、第三人称叙述、引用、条件和多个动作。用常见中英文表达；若要评估法语，请有足够法语能力的参与者独立编写与标注。样本数先按自愿参与和时间决定，逐类报告分母；这些数字不是比赛要求或总体代表性证明。

## 冻结与执行

1. 测试前确认允许标签：`none`、`come`、`home`、`walk`、`run`、`wag`、`jump`、`stop`，必要时使用多个可接受动作或 `ambiguous`。多动作请求说明是否只评估一个动作、顺序被忽略的代价，以及停止的优先规则；不要把只做最后一项称作完成整个序列。
2. 作者和两位标注者确认文件后，记录时间、版本、标签方案、文件 SHA-256、来源和已知争议，先固定题集，再运行；在结果观察前先确定计分方法与费用上限。不要让调参人员在冻结前检查并修改样例。
3. 真实 AI 测试只发送经授权的虚构句子，记录模型、日期、每条请求次数、返回和错误；调用失败不算 `none`。原始模型动作、护栏结果和网页实际执行分别记录。网页测试记录设备、网络和实际初始状态；语音识别另测，不与文字结果混算。
4. 对每类分别报告总数、可评分数、成功、错误、误动作、未执行及未完成请求；标注分歧和上下文缺失单列。不得将满意度、小样本比例或自动测试称为真实世界错误率或疗效。
5. 若据此修改模型或规则，该批题转为开发集；保留原结果和失败，不得反复使用同一批题宣布“独立通过”。再次评估应由未参与调参者准备新题并复核。

## 推荐记录字段

`id`、作者代号、输入语言、虚构输入、开始状态、两位标注者各自结果、可接受动作、分歧、模型与版本、原始模型动作、护栏动作、网页观察动作、错误/超时、评审备注。测试文件默认存放在非公开项目目录；如果材料将被公开，必须先逐项检查授权及去标识化。

## 给项目负责人的准备

先确认：① 是否有两位愿意独立标注的成年人；② 是否有未看过开发集的人愿意写测试句；③ 可接受的真实 AI 测试预算；④ 谁保管资料、何时删除。没有真人参与时，继续使用明确标记的 AI 生成探索案例，不填造参与人数、评分或结论。
