## 谁做什么

1. **出题人**：自愿成年人，尽量没有看过此前开发例子、规则和失败清单；按 `01-出题说明.md` 独立写虚构句子，保留自己的意图记录，不使用 AI 代写。
2. **两位标注者**：尽量未参与该实现或调参，分别依据 `02-标注说明.md` 标注。先只看句子与开始状态，不看出题人的意图、对方答案或模型结果。完成后再对比；保留分歧，不迫使达成一致。
3. **项目负责人**：提供虚构示例与已获许可的蓝老模型；根据 `03-现场任务和记录.md` 记录真实操作，保留失败，参与者可跳题或随时退出。

出题人、标注者和观察者应分别标明身份代号与角色。人数不够时先做可用性试运行，记录实际人员重叠，不能称作相互独立的人类盲测。两人建议用于发现分歧，并非官方指定人数。

## 执行顺序与版本冻结

1. 负责人先核验上述空项、准备明确的本地服务和能否使用 AI；如果对外传输尚未获授权，先只进行本地界面和规则步骤。填写同意说明中的联系人、保留期限与服务处理信息，然后让参与者逐项选择。未经同意不录音、截图、上传、公开引用或发送数据给第三方。
2. 用 `writer-template.csv` 收集虚构输入及作者理解。负责人复制给标注者的题目时只包含 `case_id, language, initial_state, text`，遮住作者意图；分别复制两份 `rater-template.csv`。不要向标注者展示既有结果。
3. 比对两份标注；双方一致的答案供定量记录；多解、分歧或起始状态不足的题目标记 `ambiguous` 单独讨论，不强行算对错。可以保留多个可接受动作及原因；用户要求先做 A 再做 B 不能仅因为系统做了 B 就说完整执行。
4. 在看模型输出之前，冻结最终题目、两份原始标注、争议表和版本，使用 `shasum -a 256 文件名` 记录每份文件 SHA-256 和时间；记录实际人数、语言、重复检查及谁看过哪些结果。项目源码有未提交修改时也要记录涉及文件哈希，不能只写 Git commit。
5. 经明确同意及预算确认后，使用虚构句分别跑离线规则、真实模型、服务器护栏和网页。真实模型/语音发送前说明具体第三方和数据，分别记录返回、延迟、错误、用户退出和实际费用；禁止把失败记录成 `none`。语音测试先记录口述原句、浏览器识别结果、最终动作；设备、浏览器和权限拒绝要单独记录。`result-template.csv` 只在已发生观察后填。
6. 每层分别列请求总数、成功/错误/未开始、可评分数、匹配及未匹配、错误动作、漏动作与争议，不丢弃失败。小样本只用于发现问题，不推算总体错误率，不声称安全或治疗效果。若依据这批题改程序，此题集就成为开发集；保留原文件和结果，新独立评估需要新题及独立标注。

## 文件

- `01-出题说明.md` 与 `writer-template.csv`：发给自愿出题人；不包含开发题或正确答案。
- `02-标注说明.md` 与 `rater-template.csv`：给每位标注者独立填写；作者意图要遮住。
- `03-现场任务和记录.md`：负责人使用的自愿参加说明、情境任务及观察表；材料无需真实回忆。
- `result-template.csv`：记录人工观察的各层实际结果；空文件不代表已完成测试。
- 项目原[独立测试协议](../HUMAN-INDEPENDENT-TEST-PROTOCOL.md)继续适用；静态照片对照在尚未制作同等基线时不能当成已运行实验。
