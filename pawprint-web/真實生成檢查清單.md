# 照片→3D：示範模式與第一次真實生成檢查清單

更新：2026-10-25

## A. 示範模式（不花錢，錄 demo 備用）

示範模式不會呼叫 Tripo，照片不會離開電腦。它會完整走一次「上傳 → 生成 → 綁骨 → 行走 → 下載 → 檢查」流程，但**最後的模型是內建的蓝老範例模型，不是用你的照片生成的**。畫面上的任務卡和寵物頁都會顯示「示範模式 · Demo mode (no Tripo call)」標記。

1. `npm install`，然後 `npm start`
2. 打開 http://127.0.0.1:8788/studio.html ，上傳一張寵物照片，建立任務，複製任務編號
3. 另開一個終端機：`npm run process:mock -- 任務編號 --skip-blender`
4. 回到工作室（會自動刷新），按「查看模型」

演練失敗情境（確認畫面不會壞）：

```powershell
$env:TRIPO_MOCK_FAIL="network"; npm run process:mock -- 任務編號 --skip-blender
```

可用值：`balance`、`auth`、`submit`、`network`、`generation`、`rig_check`、`billing`。用完記得 `Remove-Item Env:TRIPO_MOCK_FAIL`。

**誠信提醒：** 在比賽影片裡如果用到示範模式的畫面，請口頭或字幕說明「這是流程示範，模型為範例」。評審 Q&A 很可能問到，被發現假裝成真實生成會比沒做出來更傷。最好的情況是在交件前完成下面 B 的一次真實生成，影片用真的結果。

## B. 第一次真實生成（API 額度：2026-10-25 尚有 2,360 credits）

### 事前

- [ ] 在 **Tripo API 平台**（不是 Tripo Studio 網頁會員）為 API 帳戶儲值。Studio 會員積分不能給 API 用。
- [ ] 確認目前官方價格。程式按「生成 30 + 綁骨 25 + 一個動畫 10 = 65 積分」設計，每個任務預留 100；AI 補四視角路線再加約 10。
- [ ] `.env` 中 `TRIPO_API_KEY` 已填寫（只放在 `.env`，不要貼到聊天或上傳）
- [ ] 執行 `node server/check-config.mjs`，確認 `keyValid: true`、`enoughForOneJob: true`
- [ ] `.env` 中 `TRIPO_MOCK=false`、`ALLOW_PAID_GENERATION=true`、`TEST_BUDGET_CREDITS` ≥ 100
- [ ] 準備一張清楚的全身照：四條腿和尾巴都看得到、背景單純、光線均勻。第一次先用「直接生成」路線，不用 AI 補視角

### 執行

- [ ] 在工作室建立**新**任務（示範模式跑過的任務不能轉成真實任務）
- [ ] `npm run process -- 任務編號 --confirm-tripo-charges`
- [ ] 全程錄螢幕（這就是 demo 影片最有價值的素材）

### 出問題時

| 任務狀態 | 意思 | 怎麼做 |
|---|---|---|
| WAITING_APPROVAL＋餘額不足訊息 | 還沒花錢 | 儲值後用同一個指令重跑 |
| PAUSED_NETWORK | 已送出、查詢中斷 | 直接重跑同一個指令，只會查詢不會重複扣費 |
| SUBMISSION_UNCERTAIN | 不確定有沒有扣費 | 先到 Tripo 後台核對任務與帳單，不要重建任務 |
| REVIEW_REQUIRED（未通過四足檢查） | 彩色基礎模型已保留 | 換一張更清楚的全身照再試 |
| FAILED（計費資訊缺失或超出預期） | 已自動停止後續收費步驟 | 核對帳單，回報給我 |
| 「已有加工進程」 | 上次異常退出留下鎖 | 確認沒有 worker 在跑，再刪除 `.data/worker.lock` |

### 已知風險

程式從沒真的打過 Tripo v3，以下欄位都還沒驗證：端點路徑、`file_token`、`task_id`、`credits_consumed`、`output.model_url`、四視角的 `*_view_url`、rig-check 的 `riggable`/`rig_type`、模型版本字串。如果第一次在某一步停下來，把終端機輸出和工作室的任務訊息（不含金鑰）傳給我，通常是改一個欄位名稱的事。
