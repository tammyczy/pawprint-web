# 盲測集填寫說明（blind-test.json）

## 為什麼需要盲測集

`eval/cases.json` 是我們開發時一直在看的「開發集」，規則和訓練資料都是在看過它之後寫的，所以在它上面的分數一定偏樂觀。`eval/intent/train.json` 的種子句子也是由 AI 助手起草的。若評審在 WAICY 問答中問「你怎麼知道模型真的有效？」，唯一誠實的答案是：**拿一批從沒參與開發的人寫的句子來測**。這就是盲測集。分數低也沒關係，誠實報告比漂亮數字更重要。

## 誰來寫

- 隊員或同學，但**必須沒有看過** `train.json`、`cases.json`，也沒看過模型的錯誤清單。
- 最好 3 人以上，各寫一部分，讓說法更多樣。在 `author` 欄寫代號（例如 `classmate-A`），不要寫真名。
- 寫完之後，**負責訓練的人不可以**根據盲測結果去修改訓練資料再重測同一份盲測集；如果要改，下一輪請換一批新的盲測句子。

## 要寫多少

- 目標 **至少 80 句**。
- 七個動作（come、home、walk、run、wag、jump、stop）大致平均，每個至少 6–8 句。
- **至少 30% 是 null**（寵物不該動），其中要包含：否定句（「不要跑」「Don't jump」）、引號內的指令（他說「過來」）、故事和聊天（「我昨天去跑步」）、假設句（「如果你會飛…」）、提到動作字但不是對寵物說的話（「跑車好帥」）。
- 盡量混合語言：簡體中文、繁體中文、英文、法文；也可以加入幾句模型不支援的語言，看它會不會亂動。
- 用自己平常會說的話，不要刻意模仿說明書裡的例句。

## 每個標籤的判斷規則

| 標籤 | 意思 | 例子 |
| --- | --- | --- |
| come | 叫寵物靠近使用者 | 「過來我這裡」 |
| home | 回到出發點、窩、原位 | 「回你的小窩」 |
| walk | 慢慢走、散步 | 「陪我散步」 |
| run | 跑、衝刺、暴衝 | 「跑快一點」 |
| wag | 搖尾巴 | 「搖搖尾巴」 |
| jump | 跳、蹦 | 「跳一下」 |
| stop | 停下、休息、不動 | 「停下來」 |
| null | 寵物不該做任何動作 | 聊天、故事、否定、引號、假設 |

- 一句話裡有多個指令時，標**最後一個明確要求**；如果其中有明確的停止，標 `stop`（和規則系統一致）。
- 否定一律標 `null`，即使語氣上有「停下」的意思（例如「不要跑」）。
- 拿不準的句子就跟另一位同學討論；兩人意見不同時，在 `note` 欄寫下原因，並保留爭議（這也是很好的報告素材）。

## 檔案格式

複製 `blind-test.template.json` 為 `blind-test.json`，刪除範例列，每列格式：

```json
{"id":"b-001","text":"你能不能來我旁邊坐坐","expected":"come","lang":"zh-Hant","group":"command","author":"classmate-A"}
```

`expected` 寫動作名稱，或寫 `null`（不加引號）。`group` 可用：command、negation、quoted、non-command、hypothetical、other-language。

## 怎麼執行

```bash
node eval/intent/train.mjs      # 先訓練（若 train.json 和開發集重複會拒絕）
node eval/intent/compare.mjs    # 自動偵測 blind-test.json 並輸出 BLIND set 結果
```

結果寫在 `public/evidence/intent-comparison.json` 的 `blind` 欄位。報告時請同時列出：準確率、macro-F1，以及**錯誤動作率**（應該是 null 卻動了的比例，這是安全指標）。

## WAICY 問答時可以怎麼說

> 「開發集是我們自己寫的，所以分數偏高；我們另外請沒看過訓練資料的同學寫了 N 句盲測，結果是 …。模型在 … 類句子上還會出錯，所以我們保留規則優先、否定句永不被模型推翻的設計。」
